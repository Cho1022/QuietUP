# QuietUp 프로젝트 이력

## 1. 최초 기획

QuietUp은 층간소음 문제를 직접 대면하지 않고 전달하고, 반복 발생과 대응 과정을 확인할 수 있는 아파트 커뮤니티 서비스를 목표로 시작했습니다. 핵심 사용자 흐름은 입주민이 소음 상황을 익명으로 알리고, 대상 세대가 이를 확인해 대응 상태를 남기며, 필요한 범위에서 관리 주체가 이력을 확인하는 것입니다.

## 2. 첫 Android MVP

- 개발 기간: 2025.10 ~ 2026.01.31
- Android Java 및 XML View 기반 단일 앱 모듈로 구현했습니다.
- Firebase Authentication을 이용한 이메일 회원가입·로그인을 구현했습니다.
- 사용자 추가 정보 저장, 게시판 CRUD, Realtime Database 기반 채팅을 구현했습니다.
- 전체 사용자 범위의 소음 기록 CRUD를 구현했습니다.
- 2026.08 빌드 복구 작업에서 Debug APK 생성과 JVM 단위 테스트 1건 통과를 확인했습니다.

## 3. 기존 구현의 한계

- Android 클라이언트가 Firebase 데이터 계층에 직접 연결됩니다.
- 소음 기록이 아파트·동·호 단위로 구분되지 않습니다.
- 익명 소음 알림의 대상 지정, 수신 확인, 대응 상태, 반복 이력 관리가 완성되지 않았습니다.
- 관리 주체의 역할과 권한 범위가 구현되어 있지 않습니다.
- 자동화 테스트가 기본 예제 수준이며, 실제 기기에서의 초기 실행도 재검증하지 못했습니다.
- 소스에는 경고와 deprecated API 사용이 남아 있지만, 기준선 보존 단계에서는 광범위한 리팩터링을 하지 않았습니다.

## 4. Firebase 환경 종료와 레거시 보존

기존 Firebase 프로젝트 환경은 더 이상 운영되지 않습니다. Android 소스의 Firebase Authentication 및 Realtime Database 코드는 새 서버로 기능을 이전할 때 기존 흐름을 확인하기 위한 레거시 참고 자료로 보존합니다.

원격 Firebase 데이터가 현재 보존되어 있는지, 새 데이터베이스로 이관 가능한지는 확인되지 않았습니다. 따라서 이력 보존이나 데이터 마이그레이션 완료를 가정하지 않습니다. 서버 API 전환과 회귀 검증이 끝난 뒤 Firebase Authentication과 Database 의존성을 제거할 계획입니다.

## 5. AWS 기반 전면 개편

- 개편 기간: 2026.08 ~
- 목표 구조: Android → HTTPS REST API → Spring Boot on Amazon EC2 → Amazon RDS for MySQL
- Spring Security에서 인증·권한을 처리하고 Spring Data JPA와 Flyway로 데이터 접근 및 스키마 변경을 관리합니다.
- CloudWatch를 운영 로그와 모니터링에 사용하고, 파일 저장 요구가 확정될 때만 S3를 도입합니다.

이 구조는 전환 목표이며 현재 저장소에는 아직 Spring Boot 서버나 AWS 인프라가 구현되어 있지 않습니다.

## 6. 전환 원칙

- 검증된 Android MVP는 변경하지 않고 기준선 커밋과 태그로 먼저 보존합니다.
- Android 앱은 MySQL에 직접 연결하지 않고 HTTPS API만 호출합니다.
- 인증, 권한, 입력 검증은 서버에서 수행합니다.
- RDS는 공개 접근을 허용하지 않는 비공개 네트워크 구성을 원칙으로 합니다.
- AWS 자격 증명과 서버 비밀값은 앱이나 Git 저장소에 저장하지 않습니다.
- S3는 실제 파일 저장 요구가 있을 때만 도입합니다.
- 기존 Firebase 코드는 전환 참고용으로 유지하고 기능 이전 후 제거합니다.
- 확인되지 않은 과거 이력이나 데이터 보존 상태를 만들어내지 않습니다.
- 초기 Git 이력은 2025.10~2026.01의 MVP 개발 단계를 기능 단위로 복원해 기록했으며, 2026.08에는 빌드 가능한 기준선을 별도 커밋과 태그로 보존했습니다.
